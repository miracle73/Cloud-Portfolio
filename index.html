Infrastructure I built and run

  1. 01Owuwe infrastructure

    Live ↗

    The AWS infrastructure for a multi tenant commerce operations platform, defined entirely as code.

    Idle infrastructure should cost almost nothing, so the dev stack has no NAT gateway, no load balancer and an API that starts at zero tasks.

    AWS CDK in TypeScript builds a VPC across two availability zones, Postgres 16 on RDS in an isolated subnet with credentials in Secrets Manager, an ARM64 Fargate API pulled from ECR with scan on push, an S3 gateway endpoint so storage traffic stays private, and four SQS queues with dead letter queues for assignment timeouts, escalations, webhook intake and notifications. A monthly budget and daily cost anomaly detection alert on spend.

    • AWS CDK
    • ECS Fargate
    • RDS Postgres
    • SQS
    • Secrets Manager
    • ECR
    • S3

  2. 02Primlook

    Live ↗

    The backend platform behind a booking and payments product I built and ran end to end alone.

    Provider webhooks, not synchronous responses, are the source of truth for settlement.

    Payments are confirmed by webhooks with idempotency keys, and a reconciliation job keeps payments and bookings in agreement. Email and WhatsApp notifications run through a rate limited queue with backoff, retries and a dead letter queue so weekend booking spikes do not overwhelm sending.

    • Webhooks
    • Idempotency
    • Job queues
    • Dead letter queues
    • Node.js

  3. 03Boost Staff

    Live ↗

    Cloud and platform engineering for an on demand hospitality staffing platform, where I currently work.

    One platform serves a worker mobile app, an ops admin portal and a marketing site.

    I work on the infrastructure, delivery pipelines and deployments that the mobile app on Google Play and the App Store, the admin portal and the landing site run on.

    • AWS
    • Docker
    • CI/CD
    • React Native backend

  4. 04Portfolio delivery pipeline

    Live ↗Repo ↗

    A GitHub Actions pipeline that builds a Next.js site as static files and deploys it to GitHub Pages on every push.

    No servers to run: the build is a static export, and deploys use short lived OIDC tokens instead of stored secrets.

    The workflow installs from the lockfile, builds with the right base path, uploads the output as a Pages artifact and deploys it, with concurrency control so an older run never overwrites a newer one.

    • GitHub Actions
    • OIDC
    • Next.js static export
    • GitHub Pages
